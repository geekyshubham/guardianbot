# GuardianBot v0.2.31 fresh-repository acceptance

Verified on 2026-07-30 against the production `guardianbot-prod` DigitalOcean
control plane and six new private repositories in the Geekyshubham GitHub
account. This page contains no credentials, repository contents beyond the
generated public contract, or private infrastructure configuration.

## Control-plane concurrency fix

Fresh GitHub App discovery exposed a concurrent-delivery race: Python, Node,
Ruby, and documentation fixtures initially received two identical onboarding
issues four to five seconds apart. GuardianBot v0.2.31 serializes issue creation
per repository with a PostgreSQL advisory lock and rechecks the stable
idempotency marker after lock handoff.

  [GuardianBot v0.2.31](https://github.com/geekyshubham/guardianbot/releases/tag/v0.2.31)
- Release run:

- Source commit: `51dfac3a19f88ab7dc18a4541407986eb4840a5c`
- Image:
  `ghcr.io/geekyshubham/guardianbot@sha256:48b6e65fbafe9f5d341ea85925eefa95dd9ef97302caf6445ca69ec79bb8f0fb`
- DigitalOcean deployment: `5dd01da3-8065-4621-afd1-4155bf306eb9`

The release passed the full repository gate, image scan, CycloneDX SBOM,
GitHub provenance, keyless signing, SBOM attestation, and signed-manifest
verification. DigitalOcean then deployed that exact digest. `/healthz` and
`/readyz` returned HTTP 200. The trusted security, image, and DAST workflow
identities remained pinned to the v0.2.30 commit
`ac52fb8123b5897d8c9f67b0d3ff8ca95289a5cb`; this control-plane-only release
did not rotate consumer workflows.

The duplicate issue in each affected repository was closed with an audit
comment, leaving exactly one canonical open inventory issue in every fixture.
Docker and Swift discovery each created one issue without duplication.

## PR review and failure isolation

After each draft was marked ready, the GitHub App updated one stable
GuardianBot review comment in place. Because no production model bridge route
is configured, every comment explicitly reported `AI review unavailable: no
approved administrative backend route`. This remained advisory and did not
block deterministic scanner checks.

The Docker fixture additionally verified:

- canonical `linux/amd64` build from an immutable Node Alpine digest;
- HTTP liveness at `/healthz` and readiness at `/readyz`;
- Trivy image scanning;
- CycloneDX SBOM generation;
- report-only retention of one Critical base-image finding;
- provenance-attested validation evidence; and
- no image publication from a pull request.

The first Docker attempt also proved fail-closed behavior for an upstream image
digest that no longer resolved: the build, evidence attestation, and artifact
requirements failed. Replacing it with a currently resolvable immutable digest
made the same generic workflow pass.

## Fleet inventory

After evidence ingestion, `guardianctl inventory` returned 19 repositories:

- 16 healthy `report-only`;
- two `advisory-only` (`geekyshubham` and the documentation fixture); and
- one `not-applicable` fork.

There were no `misconfigured` or `missing expected runs` classifications.
Enforcement remains intentionally unavailable until each applicable repository
has a reviewed baseline and completes the required seven-day observation
period.

## Remaining boundary

This acceptance does not claim a live AI-backed review because no production
model credential is configured. It verifies the required no-credential
failure behavior. The seven-day enforcement transition and the scheduled
authenticated-full DAST profile remain time-gated operational evidence.
